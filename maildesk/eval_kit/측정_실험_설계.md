# Maildesk 효과 측정 실험 설계

포트폴리오에 "시간 몇 % 절감", "정확도 몇 %"를 쓰려면 아래 두 실험을 **실제로 해서 나온 숫자**만 씁니다.

---

## 실험 1 — 처음 보는 메일로 다시 채점하기 (정확도)

**왜 필요한가:** 지금의 30건은 메일·정답·분류기를 모두 Claude가 만들었기 때문에 점수가 부풀려졌을 수 있습니다.

1. [새테스트메일_양식.xlsx](새테스트메일_양식.xlsx)에 메일 15~20건과 정답을 씁니다.
   - 가능하면 Maildesk를 만들지 않은 사람(친구, 연구실 동료)이 씁니다.
   - 실제 회사·사람·거래 정보는 넣지 않습니다.
2. 엑셀을 JSON으로 바꿉니다.
   ```
   python maildesk/tools/import_testset.py maildesk/eval_kit/새테스트메일_양식.xlsx
   ```
3. Outlook 테스트 폴더에 넣습니다.
   ```
   python maildesk/connect/seed_test_folder.py --data maildesk/data/sample_emails_v2.json --all
   ```
4. 규칙 방식과 AI 방식으로 각각 채점합니다.
   ```
   python maildesk/run_eval.py --data maildesk/data/sample_emails_v2.json
   python maildesk/run_eval.py --data maildesk/data/sample_emails_v2.json --classifier cli
   ```
5. **규칙(`classify/rules.py`)이나 AI 프롬프트(`classify/llm.py`)를 v2 결과를 보고 고치지 않습니다.**
   고치면 v2도 '아는 문제'가 되어 버립니다. 고친다면 v3를 새로 만들어 다시 잽니다.

## 실험 2 — 사람 단독 vs Maildesk 보조 (처리 시간)

**질문:** 같은 메일을 처리할 때 Maildesk가 시간을 줄이는가? 놓치는 메일이 줄어드는가?

| 항목 | 내용 |
|---|---|
| 메일 | 비슷한 유형으로 섞인 세트 A, B 각 10건 (실험 1의 새 메일을 나눠 써도 됨) |
| 참가자 | 본인 + 가능하면 1~2명 |
| 조건 | **사람 단독**: Outlook에서 메일만 보고 분류·기한·회신 필요를 기록하고 회신 초안을 직접 씀 / **Maildesk 보조**: 검토 화면에서 AI 결과를 확인·수정하고 초안을 고침 |
| 순서 상쇄 | 참가자 1은 A=단독 → B=보조, 참가자 2는 A=보조 → B=단독 (익숙해지는 효과를 줄이기 위해) |
| 기록 | [시간측정_기록지.xlsx](시간측정_기록지.xlsx) — 메일마다 시작·끝 시각, 판단 결과, 초안 수정 정도 |
| 끝나는 기준 | "회신 초안을 보낼 수 있는 상태로 만들었다"까지 (실제 발송은 하지 않음) |

**계산하는 숫자**
- 평균 처리 시간 (조건별) → 시간 절감률 = 1 − 보조 / 단독
- 정확도: 각 조건의 판단 결과를 정답표와 비교 (run_eval과 같은 기준)
- 놓친 메일: 회신이 필요한데 "불필요"로 처리한 건수
- 초안 수정 정도: 수정 없음 / 조금 / 많이 / 새로 씀 비율
- 검토 화면의 '검증' 탭 → 사람 검토 기록(수정률) CSV

## 결과를 쓰는 방법 (예시 — 빈칸은 실측 후 채움)

> 사람이 직접 쓴 가상 거래처 메일 __건으로 평가했을 때, AI 분류는 1차 분류 __%, 기한 추출 __%로 규칙 기반(__%, __%)보다 정확했고, 회신이 필요한 메일을 놓친 건수는 __건 → __건으로 줄었다. 참가자 __명이 메일 __건을 처리한 실험에서 1건당 평균 처리 시간은 __초 → __초(__% 감소)였다.

- 숫자 옆에는 항상 **건수·인원·조건**을 함께 씁니다.
- 표본이 작다는 한계를 그대로 적습니다. 면접에서 오히려 신뢰를 줍니다.
